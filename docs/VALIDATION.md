- Independent-review regressions were first observed failing on the original runtime: a real TERM-resistant SteamCMD descendant continued writing after timeout/recovery, and a symlinked installation root was accepted. The repaired runtime runs SteamCMD in a dedicated process group, adopts/reaps descendants before releasing locks, and handles SIGTERM/SIGINT shutdown for metadata and install calls. `STEAMCMD_TIMEOUT` defaults to 7200 seconds; regression fixtures use 0.4 seconds. Tests assert the descendant is gone before recovery, no writes continue, failed/interrupted installs retain the stop marker, and symlinked roots/parents/manifests plus escaping cleanup paths leave outside files unchanged. A reserved base manifest is also rejected. All 12 tests, the image rebuild and the isolated Docker smoke were rerun after these fixes.
- Historical maintenance helper tests: 4 passed separately. Their captured runtime limitations remain documented; they are not enabled in the fleet.
- `COMPOSE=<standalone-compose> python3 runtime/docker_smoke.py` ran an isolated real Compose project with updater + 3 server containers, using the explicitly labeled offline Steam/process fixture. It verified host bind cfg/addons shortcuts resolve correctly, admin/config files are regular independent copies with private settings preserved across updates, all server /base mounts reject writes, automatic build 1 bootstrap, automatic build 2 application, injected build 999 installation failure retaining the stop marker and stopping all 3 games, and automatic build 3 repair/restart. Disposable containers/networks/volumes were removed afterwards.
- A separate real SteamCMD container successfully self-updated, logged in anonymously, printed app 730 public branch build ID **26393695**, and exited 0. Only metadata was requested; no CS2 game installation was downloaded. The branch layout matches runtime.public_build parsing.

Not exercised: full ~game-sized Steam installation, CS2 engine behavior through the symlink tree, plugin ABI compatibility, Workshop client downloads, actual live snapshot import, production cutover/restore, human joining, bot spawn/map transitions in CS2, or Panorama rendering/clicks. The engine's executable is copied into each private tree specifically to preserve executable-relative paths, but real CS2 acceptance is still required. Host power-loss recovery was not fault-injected; the stop marker/journal are fsynced and the installation is synced before readers resume, but this is not a snapshot rollback implementation.

The active `.github/workflows/fleet.yml` runs runtime/helper tests, Compose validation, a Linux amd64 image build and Docker fixture smoke before a separate trusted publishing job can write GHCR packages. PR jobs have read-only permissions. Local actionlint v1.7.12 validation passed; the published-image Compose layout and image-selectable smoke test were rebuilt and rerun successfully.
